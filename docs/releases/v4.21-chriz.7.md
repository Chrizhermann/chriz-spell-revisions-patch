# Spell Revisions — Chriz Balance Patch v4.21-chriz.7

A documentation-only correction of v4.21-chriz.6. Every component installs exactly the
same game resources as in v4.21-chriz.6; the only installer change is the version label
that WeiDU writes into WeiDU.log. A game that already has v4.21-chriz.6 installed needs
no update.

## Corrected sentences

- `RELEASE-NOTES.md` in all three archives, Windows downloads: "To update an installed
  `SRCB_RR_COMPAT`, replace its folder and setup executable and reinstall component 0;
  WeiDU restores the previous version's backup first." now limits this to the last
  WeiDU.log entry and says not to reinstall the component deeper in a stack (below).
- `RELEASE-NOTES.md`, verification: "Installed over the v4.21-chriz.5 component, it gave
  the same resources as a fresh install." now names the tested condition: the component
  was the last WeiDU.log entry.
- `spell_rev/changelog.md` in the full archive, v4.21-chriz.6 validation: "A local check
  applied the RR component to RR v4.92's own creatures and scripts in both orders and
  over a v4.21-chriz.5 installation of it." now names the same condition and adds that a
  reinstall deeper in a stack is not an update path.
- `SRCB_RR_COMPAT/README.md`: "Re-running the installer offers uninstall, which restores
  the prior game resources." now gives the same last-entry limit for a reinstall or an
  uninstall.

The 2026-10-20 lab showed why. Deeper in a stack, WeiDU 249 skips an installed component
with `--safe-exit`. Without it, WeiDU reinstalls every later component, and that cascade
dropped SCS components that forbid a later one.

## Contents

The game content is that of v4.21-chriz.6. Rogue Rebalancing's level-5 Chaos copies
become Hold Monster, Feeblemind or Domination, with Chaos kept at level 7; the RR
compatibility and the Lightning Bolt options recognize what they patch by meaning. See
the [v4.21-chriz.6 notes](https://github.com/Chrizhermann/chriz-spell-revisions-patch/releases/tag/v4.21-chriz.6)
for the details.

## Windows downloads

- `spell_rev-v4-21-chriz-7.zip`: full SR fork, plus the SR/RR compatibility and
  Lightning tail mini-mods and all three Windows setup executables.
- `SRCB_RR_COMPAT-v4-21-chriz-7.zip`: compatibility-only package. Install component 0
  after SR and RR 11 and/or 12.
- `SRCB_CLASSIC_LIGHTNING-v4-21-chriz-7.zip`: Lightning-only tail package; component 0
  is classic bouncing and component 1 is non-bouncing spell/wands. Do not install
  both a main-fork alternative and its tail equivalent.

Every archive contains WeiDU 249 x64, its license and manual. Main-fork and both
standalone TP2s report v4.21-chriz.7. Close the game before installing anything.
These packages do not implement automatic CEBG hotpatching. An installed
`SRCB_RR_COMPAT` can be updated in place only while it is the last entry in WeiDU.log:
replace its folder and setup executable and reinstall component 0, and WeiDU restores
the previous version's backup first. Deeper in a stack, do not reinstall it: WeiDU 249
either skips it or reinstalls every later component, which can drop some of them. The
component changes game resources, not creatures already embedded in a save, so install
it before the affected encounters are first entered. Do not reinstall SR mid-stack
merely to update.

## Verification and provenance

198 automated tests passed with real WeiDU 249. Before this release was built, the
packaging tool rebuilt v4.21-chriz.6's three archives byte for byte from its tag.

Compared with v4.21-chriz.6, the archives differ only in `RELEASE-NOTES.md`,
`spell_rev/changelog.md` and `SRCB_RR_COMPAT/README.md`, and in the `VERSION` line of
the three TP2 files. No installer code reads that version. Every test scenario,
installed once from each release, left byte-identical game files apart from that label
in WeiDU.log. So did a local check with RR v4.92's own creatures and scripts in both
install orders. Spell Revisions' main component needs a full game and was not installed
for this comparison; it is installed from the same files, apart from that `VERSION`
line.
